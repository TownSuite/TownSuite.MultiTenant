01 — Key features

Small surface, the essentials covered

Flexible configuration

Read tenant information from appsettings.json or fetch it over HTTP.

Dynamic resolution

Resolve tenant-specific connection strings at request time, or pre-resolve them all.

02 — How it works

The naming convention does the routing

Each connection string is keyed by a tenant (or alias) and the app/database type it belongs to. The resolver matches an incoming tenant id against those keys to assemble that tenant's set of connections.

In plain English — the school office

Every tenant has one real ID that never changes (e.g. tenant1) — the unique id. The same tenant can also go by nicknames, like a website hostname (developer.townsuite.com) — those are aliases. The resolver keeps a notebook pointing every nickname at the real ID, so whichever name you ask with, you get the same tenant back — its connections and app settings.

developer.townsuite.com  → tenant1
tenant1                  → tenant1   (the real ID points to itself too)

Aliases come from the connection-string names (the part before the _). The real ID comes from the HTTP response's tenantId — or, for appsettings.json, the unique-id lookup you supply. In a web app the name you ask with is usually the request's hostname.

Connection string key
{tenant/alias}_{name/dbType}
tenant id / alias
app / database
tenant1_app1 tenant1_app2 alias1_app1 tenant2_app1

03 — Installation

Add the package

Build the project in Release mode to produce the .nupkg in the bin folder. Upload it to your NuGet repository, or point a NuGet source at the folder.

04 — Service registration

Wire it up in Program.cs

One call wires up the settings, web client, config reader, and resolver. The library references no database — you supply the unique-id lookup (a delegate, or an IUniqueIdRetriever).

05 — Configuration

Two ways to read tenants

Pick a config reader: read everything from appsettings.json, or fetch tenants from an HTTP service.

Connection strings live under ConnectionStrings; tenant settings under TenantSettings. The AppSettings reader supports a single record in ConfigPairs.

Point ConfigReaderUrls at a service that returns the tenant array (see Data formats). Authenticate with a bearer token if needed.

UniqueIdPattern (legacy UniqueIdDbPattern still works) is matched against {tenant/alias}. Your retriever reads UniqueIdLookup (the legacy key SqlUniqueIdLookup still works) — the reference implementation runs it as a SQL query.
